PeerHive

Designathon · November 2025 · 5.5 hours

🏆 1st Place — Experienced Track UX Research · Prototyping

Overview

PeerHive is a social discovery platform designed to help students find mentors and mentees based on shared interests and skill proficiency. Built end-to-end in 5.5 hours at a Designathon, the project challenged our team to move fast without skipping the fundamentals.

The Problem

Students often struggle to find the right mentorship connections — existing platforms are either too broad or require institutional gatekeeping. The prompt asked us to design a solution that made meaningful peer connections more accessible and low-friction.

Research

Primary Research

  • User surveys distributed to students
  • Identified pain points with existing discovery tools
  • Mapped motivations for seeking / offering mentorship

Secondary Research

  • Reviewed platforms students currently use (LinkedIn, Discord)
  • Analyzed reviews and common frustrations
  • Identified gaps in skill-based matching

Design Process

Discover

User surveys + competitive review to define the problem space before touching Figma.

Define

Synthesized research into a clear problem statement and user needs.

Ideate

Rapid sketching and team alignment on core flows and features.

Prototype

High-fidelity prototype in HTML/CSS delivered within the time limit.

FanFest Expo

CPSC 481 — Human-Computer Interaction I · Winter 2025

HCI · Accessibility · Cross-platform

Overview

FanFest Expo is a convention navigation system designed to help attendees find panels, vendors, and events across a large venue. The project was built for CPSC 481 (Human-Computer Interaction I), applying HCI principles and WCAG accessibility standards throughout the entire design and development process.

The Problem

Convention-goers often feel overwhelmed navigating large, multi-hall events with dense schedules and limited wayfinding. The goal was to design an intuitive navigation tool that works across mobile and desktop, reduces cognitive load, and remains accessible to all users.

Design Process

Research

Studied existing event apps and identified usability gaps through HCI literature and heuristic evaluation.

Wireframes

Low and mid-fidelity wireframes for both mobile and desktop layouts.

Accessibility

Applied WCAG standards: contrast ratios, keyboard navigation, semantic HTML, ARIA labels.

Implementation

Responsive Next.js front end deployed via Vercel, matching the high-fidelity Figma prototypes.

🖼Mobile prototype
🖼Desktop prototype

Tech Used

Next.js CSS Figma Vercel Node.js

Key Decisions

Mobile-First Layout

  • Convention attendees are on the go
  • Thumb-friendly navigation zones
  • Progressive enhancement for desktop

Accessibility First

  • WCAG AA contrast compliance throughout
  • Semantic HTML for screen reader support
  • Keyboard-navigable interface

Cartify

SENG 513 — Web-Based Systems · Fall 2025

Full-Stack · Product Design · Team Lead

Overview

Cartify is a full-stack marketplace platform that combines product buying and renting into a single, cohesive experience. As team lead, I owned both the product design and GitLab collaboration, designing high-fidelity prototypes for mobile and desktop before any code was written.

The Problem

Users who want to buy or rent products are forced to use separate platforms, creating friction and fragmenting the experience. Cartify aimed to unify both models under one interface without overwhelming the user with complexity.

My Role

Design

  • Led all UI/UX design in Figma
  • Mobile and desktop high-fidelity prototypes
  • Design system and component decisions
  • User flows for buy, rent, and listing flows

Engineering

  • Project lead — managed GitLab and sprints
  • Contributed to React front-end implementation
  • Coordinated back-end integration (Node.js + MySQL)

Design Process

Define

Mapped out core user journeys: browsing, buying, renting, and listing.

Prototype

High-fidelity Figma prototypes for mobile and desktop before development began.

Build

Full-stack implementation in React, Node.js, and MySQL with Docker.

Iterate

Adjusted designs based on what surfaced during development and peer review.

NAVIS

ENEL 500 — Engineering Capstone · Fall 2025 - Winter 2026

Mobile App · BLE · Multidisciplinary

Overview

NAVIS is a smart navigation glasses system designed to improve safety and accessibility for non-motorized travellers. My contribution was the mobile companion app — built in React Native (Expo) with TypeScript — providing real-time navigation support and BLE connectivity to the hardware.

The Problem

Non-motorized travellers (cyclists, pedestrians, mobility aid users) often rely on phones for navigation, which requires looking away from the path. NAVIS offloads navigation cues to a wearable display, with the companion app serving as the configuration and control hub.

My Role — Mobile App

UX Design

  • Designed the companion app interface in Figma
  • Navigation SDK integration flows
  • BLE pairing and status UI
  • Accessibility considerations for on-the-go use

Development

  • React Native (Expo) + TypeScript implementation
  • Real-time BLE connectivity with nRF52840 MCU
  • Navigation SDK integration
  • Agile sprints with bi-weekly reviews in Jira

Design Considerations

Glanceability

App used while in motion — UI needed to communicate status at a glance.

BLE States

Clear feedback for connecting, connected, and disconnected hardware states.

Cross-team

Coordinated design decisions with hardware and firmware teams throughout.

Iteration

Designs updated as firmware capabilities evolved over the project timeline.
